# Files

What each file does. Back to the [README](../README.md).

## Project files

* `sources/main.c`: creates the application (`ch.bitminded.GamingHub`) and the hub's state struct, runs GTK's main loop, builds the window on the first activation (a later launch only brings the existing window to the front), reads each launch's options in `hub_command_line` (`--end`: a game closed; `--start`: a game started), starts the once-a-second timer (`hub_tick`), frees the struct's strings when the app ends; `hub_test` (not called: a scratch test, its body rewritten when needed; milestone 7 step 2 used it to make, read and free one game)
* `sources/inits.c`: `hub_struct_init` sets every field to a known value: `hub_computer_init` (stats, `was_plugged` to `TRUE`, `low_warned` to `FALSE`), `hub_setting_init` (the settings to their defaults), `hub_timer_init` (timer widgets to `NULL`, state) and `hub_headset_init` (pointers to `NULL`, indexes to `PA_INVALID_INDEX`), then `hub_power_init`
* `sources/inits_2.c`: `hub_power_init` (the power section's pointers to `NULL`; a second file because `inits.c` has 5 functions)
* `sources/main_build.c`: the window's layout and shared layout helpers: `hub_build_box` (a stack of pages, the headset section, the power section, the stats), `hub_image_with_label` (a theme icon at 48 px with an optional wrapping label under it), `hub_labelled` (a left-aligned label in front of a widget)
* `sources/utils.c`: `hub_setting_hub` (loads the timer settings, then labels + finding the sensor folders, then the timer widgets, once), `hub_free_hub` and `hub_gfree_hub` (split for the norm; frees what the struct owns; the libpulse connection in reverse order: disconnect, unref, adapter last; the power proxy and the BlueZ object manager if they exist; the output's address and name), `hub_keep` (replaces an owned string in a struct field, through its address: frees the old one, keeps a copy; moved here from `outputs_click.c` on 23 Nov, was `hub_mic_keep`)
* `sources/computer/`: the live stats (milestone 2)
  * `sysfs.c`: shared readers for `/sys`: `hub_find_dir` (finds a device folder by the content of one of its files, e.g. hwmon `name` = `coretemp`), `hub_find_gpu` (the DRM card that has `gt_act_freq_mhz`), `hub_read_number` and `hub_read_text` (one value from a one-value file)
  * `ram.c`: reads `/proc/meminfo`, shows used / total RAM
  * `cpu.c`: reads `/proc/stat`, shows CPU % from two samples one second apart
  * `temp_fan.c`: CPU package temperature (`coretemp`) and fan speed (`thinkpad`) on one line
  * `gpu.c`: GPU frequency (actual / maximum), from `/sys/class/drm`
  * `battery.c`: battery % and status, with the charger as fallback; `hub_battery_unplug` (one alert when the charger comes out during a session) and `hub_battery_low` (one alert at 25 % during a session, reset when plugged in), milestone 6
  * `stats_build.c`: `hub_build_stats` (the five stat labels in a box)
* `sources/timer/`: the timer and healthy-gaming features (milestone 3)
  * `settings.c`: reads `~/.config/gaming_hub/settings.ini` with GKeyFile: `hub_load_timer_settings` (called first in `hub_setting_hub`, so every widget sees the final values), `hub_key_file_error` (loads the file, reports a broken one), `hub_set_timer_settings` (the seven keys), `hub_read_setting` (one number, keeps the default on any problem), `hub_read_setting_boolean` (one `true` / `false`)
  * `session.c`: `hub_timer_manager` (all timer widgets, with `hub_create_time_spin_buttons` and `hub_timer_create_buttons`), `hub_update_timer` (once a second from `hub_tick`: time left, breaks, eye cue), `hub_update_eye` (shows and hides the eye cue)
  * `alert.c`: `hub_notify` (a desktop notification), `hub_alert` (notification and/or the bell, as ticked), `hub_wind_down_alerts` (the wind-down warning, once per session)
  * `show.c`: what puts values on screen: `hub_show_time` (seconds → `h:mm:ss` on a label), `hub_show_timer_page` (the page that matches the state), `hub_show_eye` (the eye-cue text with `eye_sec`)
  * `buttons.c`: the button callbacks: `hub_start_clicked`, `hub_pause_clicked` (Pause ↔ Resume), `hub_stop_clicked` (End session), `hub_done_clicked` (back from a break), `hub_read_plan` (reads the plan page at Start)
  * `timer_build.c`: the timer's pages: `hub_build_plan` (three columns: checkboxes, `hub_plan_box_middle` with the three fields, alarm + Start), `hub_build_session`, `hub_build_break`, `hub_build_transit` (the "Between Games" page)
  * `timer_utils.c`: `hub_timer_running` (the states in which the countdown runs: playing, break, between games)
* `sources/game/`: games coming and going (milestone 4, later the launcher of milestone 7, the library)
  * `game_events.c`: `hub_game_closed` (`--end`: a running session → between games) and `hub_game_started` (`--start`: between games → playing)
* `sources/headset/`: the "Sound" section (milestones 5–6): what I'm listening on as a row of buttons, the volume of the default output and the mic of the default input through libpulse, and a Bluetooth headset's battery from BlueZ
  * `pulse.c`: `hub_pulse_connect` (the GLib adapter, the context, the connection to the sound server, once, from `hub_activate`), `hub_pulse_state` (the context's state callback), `hub_pulse_ready` (when ready: the sink and source lists, the server info, the event callback and the subscription to sinks, sources and the server)
  * `events.c`: `hub_pulse_event` (the server's events: masks the facility and the type, then dispatches; a server change asks for the server info again; a sink appearing or disappearing, or a card change (HDMI plugged in or out), rebuilds the output buttons), `hub_sink_event` / `hub_source_event` (headset removed → off; new device → asked for by index; change of the headset → read and shown again)
  * `sink.c`: `hub_sink_list` (called once per output, then at the end: finds the default output by its name, keeps its index), `hub_show_sink` (its volume and mute on the output label, or "no device" and the controls greyed out), `hub_sink_set_buttons` (keeps a copy of its volume, puts it on the slider (not within 300 ms of a user move) and the Mute button, with their handlers blocked so nothing is sent back), `hub_sink_slider_moved` (the slider sets the volume, balance kept, mutes at 0, remembers when it moved), `hub_sink_mute_toggled` (the Mute button sets the mute)
  * `source.c`: the same five for the mic (`hub_source_…`)
  * `volume.c`: `hub_volume_percent` (a `pa_cvolume`, any number of channels, as a rounded %)
  * `default.c`: `hub_pulse_default` (the server info: stores the default output and input and asks for them, then asks for the default output by name for its address), `hub_default_sink` (its Bluetooth address `api.bluez5.address`), `hub_set_bt_address` (keeps a copy, redraws the battery), `hub_ask_default_sink` / `hub_ask_default_source` (keep a copy of the default's name, press its button, ask for it by name so the slider follows; none → greyed out)
  * `bluez.c`: `hub_bluez_connect` (BlueZ's object manager, async, from `hub_activate`), `hub_bluez_ready` (keeps it, connects its three signals straight to `hub_bluez_show` with `g_signal_connect_swapped`, first redraw), `hub_bluez_has_address` (is this object the device with that address?), `hub_bluez_find` (walks all objects, returns the match with a reference for the caller)
  * `bluez_show.c`: `hub_bluez_prop` (one cached property of one interface of an object), `hub_bluez_show` (the battery label beside the title: shown with the text for a connected Bluetooth output, hidden otherwise), `hub_bluez_text` (`Battery: N %` or `Battery: ...`, `NULL` if not connected)
  * `outputs.c`: `hub_outputs_refresh` (empties the row, asks for every output), `hub_outputs_list` (one button per usable output, skipping ports that are "not available"; at the end presses the default), `hub_sink_short_name` (`device.profile.description`, else the description), `hub_outputs_add` (a toggle button in the group that remembers the sink's name and Bluetooth address), `hub_outputs_select` (presses the default's button, handler blocked)
  * `outputs_click.c`: `hub_outputs_toggled` (a click: sets the default output, then scans the mics), `hub_mic_scan` (keeps the mic with the same Bluetooth address, and the first real non-Bluetooth mic), `hub_mic_apply` (sets the default input: the headset's mic, else the laptop's)
  * `headset_build.c`: `hub_build_headset` (the "Headset" section), `hub_build_sliders` and `hub_build_mute` (the controls, greyed out until the headset is found, with their signals), `hub_headset_build_box` (the title, the "Sound" title with the battery beside it, the row of output buttons, then two columns: output and mic, each label + slider + Mute)
* `sources/power/`: the power profile over D-Bus (milestone 6)
  * `power.c`: `hub_power_connect` (the tuned-ppd proxy, async, from `hub_activate`), `hub_power_ready` (keeps it, builds the buttons, shows the profile, follows `g-properties-changed`), `hub_power_show` (the label and the pressed button), `hub_power_changed` (redraws on a change)
  * `profiles.c`: `hub_power_profiles` (one button per entry of `Profiles`), `hub_power_add_button` (a toggle button that remembers its profile, in the group), `hub_power_select` (presses the active one, handlers blocked), `hub_power_toggled` (a click → `Properties.Set`), `hub_power_set_done` (the answer; on an error the buttons go back to the real profile)
  * `power_build.c`: `hub_build_power` (the label and the joined row of buttons)
* `sources/library/`: the game library (milestone 7)
  * `hub_game.c`: the `HubGame` GObject type, registered by hand (no `G_DECLARE_FINAL_TYPE` / `G_DEFINE_TYPE`, for the norm): `hub_game_get_type` (registers the type once with `g_type_register_static_simple`, guarded by `g_once_init_enter` / `_leave`), `hub_game_class_init` (stores `finalize`, `set_property`, `get_property` in the class, then installs the properties), `hub_game_init` (fields to `NULL`, source `GAME_MANUAL`), `hub_game_finalize` (frees the four strings, then chains up to GObject's `finalize`), `hub_game_new` (one game from a `t_game_info`, through the properties)
  * `hub_game_props.c`: `hub_game_install_props` (the five properties: four strings and the source as an int), `hub_game_set_property` (stores a copy with `hub_keep`), `hub_game_get_property` (copies out), `hub_game_cast` (the checked cast `HUB_GAME()` would give)
* `includes/gaming_hub.h`: the header every `.c` file includes; pulls in the others and holds the prototypes of `main.c`, `utils.c`, `inits.c` and `main_build.c`
* `includes/structs.h`: the structs: `t_hub` holds a `t_computer` (stat labels, sensor folders, CPU samples), a `t_settings` (timer values) a `t_timer` (timer widgets and state), a `t_headset` (libpulse's GLib adapter and context, the headset's output and mic indexes, copies of their volumes, and their labels, sliders and Mute buttons; the battery label, the row of output buttons, BlueZ's object manager, the default output's Bluetooth address, the default output's and input's names, and the mic chosen after a click) and a `t_power` (profile label, row of buttons, tuned-ppd proxy), all by value, plus the window's `stack` and the application (`app`, borrowed: `main` owns it); for the library (milestone 7): the enums `t_game_source` (Steam, emulator, manual) and `t_game_prop` (property ids), `t_hub_game` (the game object: `GObject parent` first, then source, name, platform, id, path), `t_hub_game_class` (`GObjectClass parent_class`) and `t_game_info` (the five values lent to `hub_game_new`, not owned)
* `includes/defaults.h`: the values the hub uses when the settings file doesn't set them (`HUB_DEF_…`), the low-battery level (`HUB_BAT_LOW`), and the D-Bus and PipeWire names (`HUB_PPD_…`, `HUB_BLUEZ_…`, `HUB_PA_…`, including the keys stored on the output buttons); `HUB_HEADSET_NAME` removed on 22 Nov (the hub follows the default output now); the game type's name and property names (`HUB_GAME_…`, milestone 7)
* `includes/computer.h`, `includes/timer.h`, `includes/game.h`, `includes/headset.h`, `includes/power.h`, `includes/library.h`: prototypes of `sources/computer/`, `sources/timer/`, `sources/game/`, `sources/headset/`, `sources/power/` and `sources/library/`
* `Makefile`: builds the hub and libft, with GTK4's and libpulse's flags from `pkg-config`; also writes `compile_flags.txt` for the editor; `make install` / `make uninstall` (program in `~/.local/bin`, `.desktop` file in `~/.local/share/applications`)
* `assets/historic/`: screenshots of the hub at each stage (`first_working_prototype.png`, milestone 2; `timer_done/`, milestone 3: plan, playing, eye cue, break)
* `docs/research.md`: what I tested by hand before coding (headset battery over D-Bus, MangoHud logging) and the rules the code must follow
* `docs/files.md`, `docs/basics.md`, `docs/live-stats.md`, `docs/timer.md`, `docs/auto-start.md`, `docs/headset.md`, `docs/power.md`, `docs/bluez.md`, `docs/sound.md`, `docs/library.md`: this file and how each part of the hub works, moved out of the README on 19 Nov 2026
