# Files

What each file does. Back to the [README](../README.md).

## Project files

* `sources/main.c`: creates the application (`ch.bitminded.GamingHub`) and the hub's state struct, runs GTK's main loop, builds the window on the first activation (a later launch only brings the existing window to the front), reads each launch's options in `hub_command_line` (`--end`: a game closed; `--start`: a game started), connects the window's `destroy` signal to `hub_window_destroyed`, starts the once-a-second timer (`hub_tick`, its id kept in `hub->tick_id`), frees the struct's strings when the app ends; `hub_test` (not called: a scratch test, its body rewritten when needed; milestone 7 step 2 used it to make, read and free one game; step 4 to test the KeyValues parser on a made-up manifest)
* `sources/inits.c`: `hub_struct_init` sets every field to a known value: `hub_computer_init` (stats, `was_plugged` to `TRUE`, `low_warned` to `FALSE`), `hub_setting_init` (the settings to their defaults), `hub_timer_init` (timer widgets to `NULL`, state) and `hub_headset_init` (pointers to `NULL`, indexes to `PA_INVALID_INDEX`), then `hub_power_init`; also `stack`, `sections` (24 Nov), `app` and `tick_id`
* `sources/inits_2.c`: `hub_power_init` (the power section's pointers to `NULL`) and `hub_library_init` (the library's store, picked game, labels, running process, library file and its path, the volume monitor, and since step 12 the shared selection, the inner stack of views and the last selected game to `NULL`); a second file because `inits.c` has 5 functions
* `sources/main_build.c`: the window's layout and shared layout helpers: `hub_build_box` (the "Between Games" bar above a stack of pages: the library page first, then the plan page from `hub_build_plan_page`, then the session and break pages; under it `hub->sections`, one box with the Sound section, the power section and the stats; the stack's page-change handler connected before the first page), `hub_page_changed` (the stack's `notify::visible-child-name` handler: hides `hub->sections` on the library page, shows it on every other, and rescans the library each time its page is shown; milestone 7 step 8), `hub_image_with_label` (a theme icon at 48 px with an optional wrapping label under it), `hub_labelled` (a left-aligned label in front of a widget)
* `sources/utils.c`: `hub_setting_hub` (loads the timer settings, then labels + finding the sensor folders, then the timer widgets, once), `hub_free_hub` and `hub_gfree_hub` (split for the norm; frees what the struct owns, the picked game's, the last selected game's (step 12) and the running emulator's references included (`g_clear_object`), the library file (`g_key_file_free`) and its path; the volume monitor, its handlers disconnected first (`g_signal_handlers_disconnect_by_data`: the monitor is shared in the process, so the last unref may not be ours; step 10); the libpulse connection in reverse order: disconnect, unref, adapter last; the power proxy and the BlueZ object manager if they exist; the output's address and name), `hub_keep` (replaces an owned string in a struct field, through its address: frees the old one, keeps a copy; moved here from `outputs_click.c` on 23 Nov, was `hub_mic_keep`), `hub_window_destroyed` (the window's `destroy` handler: removes the tick's source so no tick writes to freed labels while the app quits; 24 Nov)
* `sources/computer/`: the live stats (milestone 2)
  * `sysfs.c`: shared readers for `/sys`: `hub_find_dir` (finds a device folder by the content of one of its files, e.g. hwmon `name` = `coretemp`), `hub_find_gpu` (the DRM card that has `gt_act_freq_mhz`), `hub_read_number` and `hub_read_text` (one value from a one-value file)
  * `ram.c`: reads `/proc/meminfo`, shows used / total RAM
  * `cpu.c`: reads `/proc/stat`, shows CPU % from two samples one second apart
  * `temp_fan.c`: CPU package temperature (`coretemp`) and fan speed (`thinkpad`) on one line
  * `gpu.c`: GPU frequency (actual / maximum), from `/sys/class/drm`
  * `battery.c`: battery % and status, with the charger as fallback; `hub_battery_unplug` (one alert when the charger comes out during a session) and `hub_battery_low` (one alert at 25 % during a session, reset when plugged in), milestone 6
  * `stats_build.c`: `hub_build_stats` (the five stat labels in a box)
* `sources/timer/`: the timer and healthy-gaming features (milestone 3)
  * `settings.c`: reads `~/.config/gaming_hub/settings.ini` with GKeyFile (its `[library]` `view=` key is read and written by `library/library_view.c`, step 12): `hub_load_timer_settings` (called first in `hub_setting_hub`, so every widget sees the final values), `hub_key_file_error` (loads the file, reports a broken one), `hub_set_timer_settings` (the seven keys), `hub_read_setting` (one number, keeps the default on any problem), `hub_read_setting_boolean` (one `true` / `false`)
  * `session.c`: `hub_timer_manager` (all timer widgets, with `hub_create_time_spin_buttons` and `hub_timer_create_buttons`), `hub_update_timer` (once a second from `hub_tick`: time left, breaks, eye cue), `hub_update_eye` (shows and hides the eye cue)
  * `alert.c`: `hub_notify` (a desktop notification), `hub_alert` (notification and/or the bell, as ticked), `hub_wind_down_alerts` (the wind-down warning, once per session)
  * `show.c`: what puts values on screen: `hub_show_time` (seconds → `h:mm:ss` on a label), `hub_show_timer_page` (the page that matches the state; no session and between games → the library, with the "Between Games" bar shown only between games, since milestone 7 step 8), `hub_show_eye` (the eye-cue text with `eye_sec`)
  * `buttons.c`: the button callbacks: `hub_start_clicked` (launches the picked game first through `hub_launch`; a failed or refused launch changes nothing), `hub_pause_clicked` (Pause ↔ Resume), `hub_stop_clicked` (End session), `hub_done_clicked` (back from a break), `hub_read_plan` (reads the plan page at Start)
  * `timer_build.c`: the timer's pages: `hub_build_plan` (three columns: checkboxes, `hub_plan_box_middle` with the three fields, alarm + Start), `hub_build_session` (with the "Starting … / Playing …" label on top), `hub_build_break`, `hub_build_transit` (since 27 Nov the slim "Between Games" bar above the stack: label, countdown, End Session, in a `GtkCenterBox`), `hub_build_transit` (the "Between Games" page)
  * `timer_utils.c`: `hub_timer_running` (the states in which the countdown runs: playing, break, between games)
* `sources/game/`: games coming and going (milestone 4, later the launcher of milestone 7, the library)
  * `game_events.c`: `hub_game_closed` (`--end`: a running session → between games), `hub_game_started` (`--start`: between games → playing; no session → the plan page with no game; during a session → "Playing …") , `hub_show_playing` (the session page's label: a format define with the picked game's name, or empty) and `hub_game_exited` (the emulator ended: exit code line if not 0, then, if it's still the watched process, drop it and `hub_game_closed`)
  * `launch.c`: starting games (milestone 7 step 8): `hub_launch_steam` (`steam://rungameid/<id>` through `g_app_info_launch_default_for_uri`, one error line on failure), `hub_launch` (the dispatcher used by Start and by a pick between games: a picked game that isn't Ready → one line, `FALSE`, step 10; no picked game → go ahead; Steam → its link; other games → `hub_launch_emulator`; "Starting …" on success), `hub_launch_emulator` (the argv → `g_subprocess_newv`, the process kept as `t_library.running`, watched with `g_subprocess_wait_async`)
  * `launch_argv.c`: `hub_launch_argv` (the game's `command` split with `g_shell_parse_argv`, a new argv the caller owns) and `hub_launch_fill` (`gamemoderun` first, then each word copied, `%f` replaced by the game's path as one element)
* `sources/headset/`: the "Sound" section (milestones 5–6): what I'm listening on as a row of buttons, the volume of the default output and the mic of the default input through libpulse, and a Bluetooth headset's battery from BlueZ
  * `pulse.c`: `hub_pulse_connect` (the GLib adapter, the context, the connection to the sound server, once, from `hub_activate`), `hub_pulse_state` (the context's state callback), `hub_pulse_ready` (when ready: the sink and source lists, the server info, the event callback and the subscription to sinks, sources and the server)
  * `events.c`: `hub_pulse_event` (the server's events: masks the facility and the type, then dispatches; a server change asks for the server info again; a sink appearing or disappearing, or a card change (HDMI plugged in or out), rebuilds the output buttons), `hub_sink_event` / `hub_source_event` (headset removed → off; new device → asked for by index; change of the headset → read and shown again)
  * `sink.c`: `hub_sink_list` (called once per output, then at the end: finds the default output by its name, keeps its index), `hub_show_sink` (its volume and mute on the output label, or "no device" and the controls greyed out), `hub_sink_set_buttons` (keeps a copy of its volume, puts it on the slider (not within 300 ms of a user move) and the Mute button, with their handlers blocked so nothing is sent back), `hub_sink_slider_moved` (the slider sets the volume, balance kept, mutes at 0, remembers when it moved), `hub_sink_mute_toggled` (the Mute button sets the mute)
  * `source.c`: the same five for the mic (`hub_source_…`)
  * `volume.c`: `hub_volume_percent` (a `pa_cvolume`, any number of channels, as a rounded %)
  * `default.c`: `hub_pulse_default` (the server info: stores the default output and input and asks for them, then asks for the default output by name for its address), `hub_default_sink` (its Bluetooth address `api.bluez5.address`), `hub_set_bt_address` (keeps a copy, redraws the battery), `hub_ask_default_sink` / `hub_ask_default_source` (keep a copy of the default's name, press its button, ask for it by name so the slider follows; none → greyed out)
  * `bluez.c`: `hub_bluez_connect` (BlueZ's object manager, async, from `hub_activate`), `hub_bluez_ready` (keeps it, connects its three signals straight to `hub_bluez_show` with `g_signal_connect_swapped`, first redraw), `hub_bluez_has_address` (is this object the device with that address?), `hub_bluez_find` (walks all objects, returns the match with a reference for the caller)
  * `bluez_show.c`: `hub_bluez_prop` (one cached property of one interface of an object), `hub_bluez_show` (the battery label beside the title: shown with the text for a connected Bluetooth output, hidden otherwise), `hub_bluez_text` (`Battery: N %` or `Battery: ...`, `NULL` if not connected)
  * `outputs.c`: `hub_outputs_refresh` (empties the row, asks for every output), `hub_outputs_list` (one button per usable output, skipping ports that are "not available"; at the end presses the default), `hub_sink_short_name` (`device.profile.description`, else the description), `hub_outputs_add` (a toggle button in the group that remembers the sink's name and Bluetooth address), `hub_outputs_select` (presses the default's button, handler blocked)
  * `outputs_click.c`: `hub_outputs_toggled` (a click: sets the default output, then scans the mics), `hub_mic_scan` (keeps the mic with the same Bluetooth address, and the first real non-Bluetooth mic), `hub_mic_apply` (sets the default input: the headset's mic, else the laptop's)
  * `headset_build.c`: `hub_build_headset` (the "Headset" section), `hub_build_sliders` and `hub_build_mute` (the controls, greyed out until the headset is found, with their signals), `hub_headset_build_box` (the title, the "Sound" title with the battery beside it, the row of output buttons, then two columns: output and mic, each label + slider + Mute)
* `sources/power/`: the power profile over D-Bus (milestone 6)
  * `power.c`: `hub_power_connect` (the tuned-ppd proxy, async, from `hub_activate`), `hub_power_ready` (keeps it, builds the buttons, shows the profile, follows `g-properties-changed`), `hub_power_show` (the label and the pressed button), `hub_power_changed` (redraws on a change)
  * `profiles.c`: `hub_power_profiles` (one button per entry of `Profiles`), `hub_power_add_button` (a toggle button that remembers its profile, in the group), `hub_power_select` (presses the active one, handlers blocked), `hub_power_toggled` (a click → `Properties.Set`), `hub_power_set_done` (the answer; on an error the buttons go back to the real profile)
  * `power_build.c`: `hub_build_power` (the label and the joined row of buttons)
* `sources/library/`: the game library (milestone 7)
  * `hub_game.c`: the `HubGame` GObject type, registered by hand (no `G_DECLARE_FINAL_TYPE` / `G_DEFINE_TYPE`, for the norm): `hub_game_get_type` (registers the type once with `g_type_register_static_simple`, guarded by `g_once_init_enter` / `_leave`), `hub_game_class_init` (stores `finalize`, `set_property`, `get_property` in the class, then installs the properties), `hub_game_init` (fields to `NULL`, source `GAME_MANUAL`, state `GAME_READY`), `hub_game_finalize` (frees the strings, `drive` included, then chains up to GObject's `finalize`), `hub_game_new` (one game from a `t_game_info`, through the properties; no caller since step 9, decided at step 18)
  * `hub_game_props.c`: `hub_game_install_props` (the seven properties: five strings, `command` added 27 Nov, the source as an int, and `state` as a **read-only** int, step 10), `hub_game_set_property` (stores a copy with `hub_keep`; never called for `state`), `hub_game_get_property` (copies out), `hub_game_cast` (the checked cast `HUB_GAME()` would give), `hub_game_same` (are two game objects the same game: same source, then `id`, or `name` when there's no `id`: the rule of `hub_library_key`, without building strings; step 12); full at 5 functions
  * `library_store.c`: `hub_library_rescan` (the Steam and platforms scans write into the library file in memory, then `hub_library_fill` builds the list from it, `hub_library_check` works out the states and `hub_library_save` writes it; milestone 7 steps 8–10; since step 12 the selected game is kept in `last` first and selected again at the end), `hub_library_reselect` (after a rescan: the new object that is the same game as `last` selected again, then `hub_view_focus`; step 12). `hub_library_add` was deleted at step 9 (no caller left)
  * `library_rows.c`: the list's row recipe, and the state code shared by rows and tiles: `hub_row_setup` (an empty row: name label that expands, platform label, state label), `hub_row_bind` (fills a row with one game's name, platform and state, then listens to the game's `notify::state`), `hub_item_state` (a row's or tile's last child is the state label: empty, `Plug in <drive>` or `Not installed`, and the widget dimmed when not Ready; the opacity set again at every bind because items are reused), `hub_item_notify` (a game's state changed → `hub_item_state` on its row or tile), `hub_item_unbind` (both factories: stops listening before the item gets another game); `hub_row_state` / `_notify` / `_unbind` renamed `hub_item_…` at step 12; full at 5 functions (step 10)
  * `keyvalues.c`: the reader for Valve's KeyValues text (Steam's `.vdf` / `.acf` files): `hub_kv_skip_space` (whitespace, counting lines), `hub_kv_read_string` (one quoted string, a copy the caller frees), `hub_kv_next` (the tokenizer: string, `{`, `}`, end or error), `hub_kv_skip_block` (a whole `{ … }` block, nested ones included), `hub_kv_enter` (into the block of a given key at the current level)
  * `keyvalues_2.c`: `hub_kv_load` (a whole file into a buffer the caller frees, the cursor pointed at it), `hub_kv_pair` (one key and its value, with clear ownership for each result), `hub_kv_take` (moves a string into a slot instead of copying it)
  * `steam.c`: the Steam source: `hub_steam_scan` (reads `libraryfolders.vdf`, reports a broken file with its line; since step 9 the Steam functions write each game into the library file instead of the store), `hub_steam_folders` (each library block), `hub_steam_lib_path` (a block's `path`), `hub_steam_library` (every `appmanifest_*.acf` in a library's `steamapps/`; a missing folder is skipped; since step 12 a library on a drive that isn't mounted is skipped **before** its folder is touched, with `hub_state_present`, so an unplugged automount can't freeze the window), `hub_steam_app_free` (the four strings of a `t_steam_app`)
  * `steam_app.c`: one manifest: `hub_steam_app` (load, read, skip or add, free), `hub_steam_app_keep` (a wanted value moved into its field), `hub_steam_app_read` (the pairs of `AppState`), `hub_steam_app_skip` (missing fields, `LastOwner` `0`, the skip list), `hub_steam_app_add` (trimmed name, install path, into the store)
  * `platforms.c`: the emulator source (step 6): `hub_platforms_scan` (loads `~/.config/gaming_hub/platforms.ini` with `hub_key_file_error`: missing = quiet, broken = an error line; one `hub_platform_read` per section), `hub_platform_read` (a section's `folder`, `extensions` and `command` into a `t_platform` it owns; a section missing one gives a line and is skipped; `~/` expanded; the struct lent down as `const t_platform *`), `hub_platform_ext_ok` (is the text after the last dot one of the extensions, case ignored), `hub_platform_folder` (every matching file in the folder; a missing folder is skipped quietly; a folder on a drive that isn't mounted is skipped without touching it, step 12), `hub_platform_add` (one `GAME_EMULATOR` game: file name, section as platform, full path, the section's command); full at 5 functions
  * `paths.c`: `hub_path_expand` (a leading `~/` in an owned string replaced in place by the home folder; used for `folder=`, later for manual entries)
  * `names.c`: a dump's name from its file name (step 7): `hub_name_parse` (stem without the extension; the title is always set), `hub_name_split` (`Title (Region) [ID]` parsed from the end), `hub_name_clear` (frees a `t_dump_name`)
  * `disc.c`: the GameCube / Wii disc header (step 7): `hub_disc_id` (the first 32 bytes; a Wii or GameCube magic word → the 6-byte game ID into the caller's buffer), `hub_disc_check` (the disc's ID when the name has none; one warning line when they differ)
  * `library_pick.c`: picking a game (milestone 7 step 8): `hub_library_activate` (the `activate` signal of **both** views, double-click or Enter; its first parameter is a `GtkWidget *` since step 12, unused: the game is read from the shared selection, where `position` counts, so it stays right with step 13's filters; it becomes `picked`; between games it launches at once and `hub_game_started` carries the session on; otherwise `hub_library_plan`), `hub_library_plan` ("Game: …" on the plan page, plan page shown; split out at step 12 for the 25 lines), `hub_build_plan_page` (the plan page: a `GtkCenterBox` row with Back to library and the "Game:" label, then the plan), `hub_library_back` (drops the picked game, back to the library)
  * `library_build.c`: `hub_build_library` (the library file loaded, the drives watched, the store → the shared single selection (`t_library.selection`, borrowed), then the inner stack (`t_library.views`, borrowed) with `"list"` and `"grid"`, the saved view restored with `hub_view_load`, and only then its `notify::visible-child-name` connected to `hub_view_changed`; the store is filled by the rescan; step 12), `hub_build_list` (the list: row factory, list view on the selection, which takes its original reference, `activate`, scrolled window; split out at step 12), `hub_build_library_page` (the stack's `"library"` page: a `GtkCenterBox` row with the List / Grid `GtkStackSwitcher` at the start and Refresh at the end, then the views; the switcher is pointed at the inner stack once it exists), `hub_library_refresh` (the button: rescan)
  * `library_tiles.c`: the grid (step 12): `hub_tile_slot` (the 160 × 240 slot, a plain `card` block with a 64 px icon in the middle; the cover goes here at step 17), `hub_tile_setup` (an empty tile, centred in its cell: slot, name (2 lines at most, then "…", at most 18 characters wide so it never widens the tile), platform tag, state line **last**), `hub_tile_bind` (the source icon (`steam`, else `applications-games-symbolic`), name, platform, `hub_item_state`, and `notify::state` with the tile as data), `hub_build_grid` (tile factory, `g_object_ref` on the shared selection before `gtk_grid_view_new` takes it (each view owns one reference), up to 20 columns, `activate`, scrolled window)
  * `library_view.c`: which view is shown (step 12): `hub_view_focus` (the visible view's selected game scrolled into view with keyboard focus, `gtk_grid_view_scroll_to` or `gtk_list_view_scroll_to` with `GTK_LIST_SCROLL_FOCUS`; nothing selected → the view focused), `hub_view_save` (`view=` in `[library]` of `~/.config/gaming_hub/settings.ini`: loaded fresh with comments kept, missing is fine, a broken file is left alone with one line, saved atomically), `hub_view_changed` (the inner stack's `notify::visible-child-name`: save, then focus), `hub_view_load` (at startup: `view=grid` → the grid; missing → the list, quiet; anything else → the list + one line)
  * `library_file.c`: the hub's library file `~/.local/share/gaming_hub/library.ini` (step 9): `hub_library_load` (once at startup: missing = empty and quiet, broken = one line, renamed to `library.ini.broken`, start empty), `hub_library_entry` (one section → one game, the owned strings moved straight into its fields; no `name=` → skipped with one line), `hub_library_fill` (empties the store, one game per section), `hub_library_save` (makes the folder, writes the file atomically)
  * `library_entry.c`: one game into the library file (step 9): `hub_library_key` (its section name, `steam:<appid>` / `emulator:<disc ID>` / `manual:…`; no ID → the name escaped), `hub_library_set` (one value, or the key removed when the value is `NULL`), `hub_library_remember` (the six keys of one game; called by both scanners)
  * `library_state.c`: each game's state (step 10), from the kernel's mount list, without touching an unmounted disk: `hub_state_under` (is a path inside a mount point: the mount path's length, `1` for `/`, `0` if not; `/mnt/Steam2TB-old` is not inside `/mnt/Steam2TB`), `hub_state_mount` (the longest mount point holding a path, and whether a non-`autofs` entry is mounted there), `hub_game_check` (one game: no path → Ready; only `autofs` → Drive not connected, `drive` = the mount point; else the path tested → Ready / Not installed), `hub_library_check` (the mount list once, every game checked and `notify::state` sent, the list freed), `hub_state_present` (is a folder's drive really mounted, from the mount list: the scans skip folders on unplugged drives; step 12); full at 5 functions
  * `library_drives.c`: live drives (step 10), GIO's volume monitor: `hub_drives_watch` (the monitor kept in `t_library.volumes`; `volume-removed`, `mount-added`, `mount-removed`, `volume-added` connected), `hub_drives_changed` (→ `hub_library_check`), `hub_drive_added` (a disk appeared: re-check, then each waiting drive opened once, a `GHashTable` as the set of drives already started), `hub_drive_wake` (one drive opened in the background with `g_file_enumerate_children_async`, so systemd mounts it without freezing the window), `hub_drive_woken` (the open finished: result freed, re-check); full at 5 functions
* `includes/gaming_hub.h`: the header every `.c` file includes; pulls in the internal headers (the system ones libft and GTK don't bring moved to `structs.h` on 28 Nov: `<fcntl.h>` for `open`, `<glib/gstdio.h>` for `g_rename`, `<gio/gunixmounts.h>` for the mount list) and holds the prototypes of `main.c`, `utils.c`, `inits.c` and `main_build.c`
